# 助理 UI 详细设计（Assistant v4 UI Spec）

> 状态：v1.0（2026-11-08）
> 关系：`docs/assistant-v4.md` 的落地细化——逐页面、逐组件、逐状态的规格（尺寸、色彩、动效、手势、边界态）。机制语义（提案裁决、CRDT、工具协议）不在此重复，分别见 `docs/crdt.md` 与 `design-v3-details.md`。
> 实现基线：`mobile/lib/ui/assistant/` 现状（chat_page / conversations_page / approvals_page / model_picker / attachment_picker + widgets/）。每节末尾「改动点」给出从现状到规格的具体差异。

---

## 1. 设计令牌（Tokens）

助理域一律使用下列令牌，禁止散写魔法数；与全 App 既有规范（`ui-structure.md` §7、`ux-fixes-2026-11.md` §3）一致的部分直接引用。

### 1.1 色彩（全部取自 ColorScheme，不新增色板）

| 令牌 | 值 | 用途 |
|---|---|---|
| 用户消息底 | `primary` / 文字 `onPrimary` | 用户 pill |
| 助理正文 | 无底（页面底色）/ 文字 `onSurface` | 全宽时间线 |
| 步骤卡底 | `surfaceContainerHighest` 60% 透明度 | 思考块/工具块（沿用现状） |
| 提案卡底 | `surfaceContainerHigh` | 提案卡 |
| 提案状态色 | pending `amber.shade700` / applied `green.shade600` / rejected `onSurfaceVariant` / failed `error` / **superseded `tertiary`** | 左边条 + 状态标（新增 superseded，蓝灰取 tertiary 与红绿黄区分） |
| 通道状态点 | 在线 `green.shade600` / 远程 `onSurfaceVariant` / 不可用 `error` | 8px 圆点，全助理域同一语义 |
| 错误横幅 | `errorContainer` / `onErrorContainer` | 回合错误、诊断 |

状态色永不单独立义：必配图标或文字（色盲友好）。

### 1.2 字阶与排版

| 角色 | 规格 |
|---|---|
| 助理正文 / 用户消息 | 16sp / lineHeight 1.6（现状 15/1.45 上调，对话正文阅读优先） |
| markdown 标题 | h1 20 / h2 18 / h3 17，字重 700/700/600 |
| 行内代码 / 代码块 | 13sp monospace；代码块底 `surfaceContainerHighest`，圆角 8，内边距 10，右上角常驻复制按钮（见 §4.4） |
| 步骤卡/提案卡摘要 | 13sp；元信息（工具名/耗时/状态）11sp |
| 时间戳 | 不常驻显示（现状气泡角 10sp 时间戳移除），收进长按菜单「详情」 |
| 数字 | 全域等宽数字（tnum 已有）；耗时/计数变化用 AnimatedSwitcher 位次滚动 |

### 1.3 间距 / 圆角 / 命中区

- 页面水平边距 12；消息流条目垂直间距：用户消息间 8，助理段落间 4，卡片区间距 6；
- 圆角：用户 pill 16（右下小角 4）；提案卡 12；步骤卡 8；输入胶囊 22；建议 chip 胶囊全圆角；
- 命中区 ≥48×48dp：提案双键、chip 删除叉、行内图标一律 `TapTargetSize.padded` 或透明 padding 补足（视觉尺寸可小）；
- 列表/对话流底部留 88px 可滚动空白（与任务页一致，给 FAB/输入区让位）。

### 1.4 动效

| 场景 | 时长 / 曲线 |
|---|---|
| 流式文本淡入 | 280ms（现状，保留）+ 段间新增 120ms 交错 |
| 卡片展开/收起 | 200ms easeOutCubic + 高度动画 |
| 提案卡状态迁移（pending→applied 等） | 250ms：状态边条颜色过渡 + 双键淡出 |
| 回合开始（用户消息上屏） | 150ms 淡入 + 8px 上移 |
| 页面/分区切换 | 250–300ms（沿用全 App 分档，禁止超 300ms） |
| 呼吸圆点 | 900ms 往返（现状保留，唯一常驻循环动画） |

## 2. 对话列表页（conversations_page）

### 2.1 结构

```
AppBar「助理」  actions: [搜索🔍 | 待确认区(角标) | 模型]
列表
└─ 对话行（见 §2.2）
FAB 新对话
空态：插画图标 +「和助理一起整理你的库」+ [新建对话] 按钮
```

「模型」入口从对话页顶栏之外保留在列表页（全局默认模型管理），对话页顶栏只剩「本对话模型」。

### 2.2 对话行规格

```
┌────────────────────────────────────────────┐
│ [状态点] 标题（1 行省略）          置顶📌 │
│ 副标题：模型名 · 相对时间                   │
│         或 在途态：● 思考中 12s             │
│         或 待审批：◔ 3 项待你审批           │
└────────────────────────────────────────────┘
行高 64，垂直节奏 4
```

- **副标题三态优先级**：在途回合（呼吸点 + 阶段 + 秒数，等宽数字）> 有待审批提案（amber 计数）> 默认（模型名 · 相对时间「昨天/3天前/MM-dd」）；
- **状态点**（标题前 8px）：该对话绑定模型的通道状态（LinkModel 在线绿 / 远程灰 / 配置失效红）；
- **手势**：左滑 → [置顶/取消置顶] [删除]（删除红）；长按 → 上下文菜单（重命名/置顶/导出/删除）；点击 → 进对话；
- **排序**：置顶区（按最近更新）→ 普通区（按最近更新），区间细分隔线；
- **删除**：确认 dialog 文案保持「其待确认提案会保留在待确认区」。

### 2.3 搜索

AppBar 搜索图标 → 搜索态（SearchAnchor 模式）：按标题 + 消息全文匹配，结果行高亮命中片段（标题命中显示标题，正文命中显示片段上下文），点击进对话并滚动定位到命中消息。

### 2.4 改动点（现状 → 规格）

`conversations_page.dart`：副标题由「仅时间」升级为三态；加状态点；加置顶（`conversations` 加列 `pinned INTEGER DEFAULT 0`，v11 迁移）；左滑手势替换纯 PopupMenu；空态由单行文字升级为标准空态；AppBar 加搜索。

## 3. 对话页（chat_page）——核心规格

### 3.1 三段式结构

```
┌─ 顶栏 ────────────────────────────────┐
│ ← 标题(1行)                           │
│   ● 模型名 · 通道状态        [⋮]      │  ← 点击模型行唤选择器
├─ 消息流（Expanded ListView）──────────┤
│ 建议 chips（仅空对话）                │
│ 用户 pill / 助理时间线 / 步骤卡 / 提案卡│
│ 错误横幅（回合出错时）                │
├─ 输入区 ──────────────────────────────┤
│ 敏感信息提示条（草稿含图时，现状保留）│
│ 附件条 + 预算条                       │
│ [📎][🖼] 输入胶囊            [发送/停止]│
└───────────────────────────────────────┘
```

### 3.2 顶栏

- 标题一行省略；副标题行 = 状态点 + 模型名 + 通道文字（「电脑端」「远程」「不可用」），整行可点击 → 模型选择器（选择模式）；
- 回合中切换模型**允许但须明示后果**（决策，2026-11-08）：点击模型行时若当前对话有在途回合，先弹说明 sheet（不直接进选择器）：
  - **「切换模型」确认 sheet**，逐条列明后果：
    1. 当前正在进行的回合**不受影响**——它已按旧模型的能力组装上下文（含工具说明书与附件展开），会用旧模型跑完；
    2. 切换**从下一回合起生效**；
    3. 若新模型不支持 vision，已挂的图片附件自下回合起**不再附带图像**（仅文字声明）；
    4. 上下文上限可能变化，附件预算条按新模型重算（超限附件保持挂载但发送时按 §3.6 预算规则拦截）。
  - 按钮：[仍然切换]（进选择器）/ [取消]；无在途回合时直接进入选择器，切换成功后 SnackBar 提示「下一条消息起使用 <新模型名>」；
- ⋮ 菜单：重命名 / 导出对话（markdown，写入文件区）/ 清空重开（保留待确认提案，确认 dialog）/ 删除对话（红，确认 dialog）；
- 移除现状 AppBar 的「待确认区」图标（对话内已有内联审批；待确认区保留在列表页），顶栏不超过 2 个 action。

### 3.3 消息流：条目类型与渲染

| 条目 | 形态 | 规格 |
|---|---|---|
| 用户消息 | 右对齐 pill | primary 实心，圆角 16/右下 4，最大宽 82%（上限 560），内边距 12/10，16sp/1.6 onPrimary，纯文本；附件卡栈在 pill 下方独立成行（现状 pill 内嵌改为外置，避免 pill 过宽） |
| 助理正文 | 全宽时间线 | 无气泡、页面水平 12 内边距内通栏；markdown 渲染（§1.2 字阶）；`selectable: true` 保留 |
| 思考块 | 步骤卡 | 沿用现状组件；默认收起，流式期间头部「思考中 Ns」；回合结束后自动收起并显示「已思考 Ns」 |
| 工具块 | 步骤卡 | 同上；标题 = 提案摘要（自然语言），副标 = 状态；**展开详情新增「查看提案」跳转**（写工具） |
| 提案卡 | 内联卡 | 见 §4；挂在产出它的 assistant 消息段之后（现状行为保留） |
| 附件卡 | 卡栈 | 沿用 AttachmentCardStack；媒体预览/文档文件块不变 |
| 分叉分隔线 | 细分隔 | 编辑/重试截断点处：发丝线 + 居中「已从这里重新生成」12sp onSurfaceVariant |
| 错误横幅 | errorContainer 卡 | 图标 + 错误摘要 + 行内 [重试] 按钮（现状只有文案） |

### 3.4 流式渲染

沿用现状分段管线（`ChatStreamSegment`：思考/工具/正文交错），规格化四点：

1. **平滑追加**：`FadeInStreamingText` 的 holdback 从「末尾两词」放宽为「末尾一个完整 token 段」，段落间新增内容交错淡入 120ms，消除长段一次性跳变；
2. **光标**：呼吸圆点仅出现在活动尾部文本段末尾；思考/工具阶段光标单独成行（现状行为保留）；
3. **段落落定**：`settle()` 时 200ms 内从流式样式过渡到落定样式（无边距跳动——容器从流式气泡变为全宽时间线的过渡用 AnimatedSize + 淡入）；
4. **中断恢复**：流中断（网络断/取消）时未闭合段标记「已中断」灰标，已生成正文保留，输入区上方出现 [继续] 快捷条（点击以「继续」为输入重跑回合，附件沿用原文）。

### 3.5 滚动行为

- 发送/收到首 token：平滑滚到底（300ms easeOutCubic）；
- 流式期间：用户已在底部（距底 <48px）→ 跟随滚动；用户上翻阅读 → 不跟随，右下角浮出「↓ 新内容」回底按钮（带未读新段落提示点）；
- 进入页面：硬跳到底（现状保留）；
- 键盘弹出：保持底部跟随（adjustResize 已有）。

### 3.6 输入区

- 胶囊容器（现状保留）：左端 [附件📎] [截图🖼] 两键收进一个 [+] 展开钮（单手拇指区，减少胶囊内拥挤）；展开为上半屏 sheet：附件 / 相册截图 / 快捷指令三组；
- **`/` 指令**：输入框首字符为 `/` 时弹指令面板（浮于输入区上方）：`/整理收件箱` `/总结` `/建任务` `/翻译`——选择后插入对应提示词模板文本（可继续编辑），面板随输入非 `/` 开头自动消失；
- **附件条**：现状 chip 横滑保留；右端新增**预算条**（宽 48 的细条 + 百分比，≤80% 灰、>80% amber、>100% 红且发送键禁用 + tooltip「附件超出模型上下文，请移除部分附件」）；token 估算 = 字符数/2（CJK 保守估计），上限取模型配置（无数据按 32k）；
- **发送键**：回合中同位置变红色停止键（现状保留）；停止后输入区上方出现 [继续] 快捷条（§3.4-4）；
- **防连击**：点击发送后按钮立即转 busy 态直至回合 started 事件返回；
- **键盘**：发送后不收键盘（连续对话）；点消息流空白处收键盘。

### 3.7 长按与消息操作

长按任意消息 → sheet 菜单（现状结构保留，补齐）：

| 消息类型 | 菜单项 |
|---|---|
| 用户 | 复制 / 编辑（重跑）/ 撤回 / 详情（时间、附件数、token 数） |
| 助理 | 复制 / 重试 / 详情（模型、耗时、token 用量、提案数） |
| 提案卡 | 通过 / 拒绝 / 查看 diff 详情 / 复制摘要 |

回合进行中允许长按浏览「详情」，但重试/编辑/撤回仍禁用（现状行为保留，tooltip 说明「等本回合结束」）。

### 3.8 空态与建议 chips

空对话消息流 = 居中助理图标 + 「有什么可以帮你？」+ 下方建议 chips（横滑，最多 3 条，按真实数据生成）：

| 条件 | 建议 |
|---|---|
| 收件箱 pending > 0 | 「帮我整理收件箱（N 条未处理）」 |
| 今天有未完成任务 | 「排一下今天的安排（M 项）」 |
| 以上都无 | 「记一篇笔记」 |

点击 = 填入输入框并立即发送。数据为空时不显示对应 chip，全空时只显示通用 chip。

### 3.9 改动点（现状 → 规格）

`chat_page.dart`：①助理消息去气泡改全宽（`_bubbleDecoration` 仅用户保留）；②时间戳移除常驻、入详情菜单；③顶栏副标题化 + 移除待确认区 action；④[+] 展开钮整合两个附件入口；⑤`/` 指令面板；⑥预算条；⑦[继续] 快捷条；⑧回底按钮与跟随滚动策略；⑨分叉分隔线；⑩错误横幅加 [重试]；⑪空态建议 chips。流式分段/草稿附件/回合自持等机制不动。

## 4. 提案卡（proposal_card）与审批交互

### 4.1 卡片状态机

```
pending ──通过──▶ applying（行内转圈，<1s）──▶ applied（绿，10s 内可撤销）
   │                                       └──▶ failed（红 + 原因 + [重试]）
   ├──拒绝──▶ rejected（灰，沉底）
   └──审批时合并裁决──▶ superseded（tertiary + 「已被覆盖」说明 + [重新生成]）
                        或 rebase 生效 → applied 带「已基于最新状态生效」角注
```

### 4.2 卡片解剖（full 密度，对话内联与待确认区共用）

```
┃ [图标] 摘要（2 行省略）              [状态标]
┃ 类别 · 工具名 · 相对时间
┃ ── diff 区（按工具类型，§4.3）──
┃ [✓ 通过(filled)]  [✕ 拒绝(outlined)]        ← pending
┃ [已生效 · 撤销]                              ← applied 10s 内
```

- 左边条 3px 状态色；内边距 12/8；圆角 12；
- 双键命中区 48dp；「通过」filled、「拒绝」outlined（主从分明）；
- compact 密度（历史区/次要位置）= 摘要行 + 状态标，无 diff 无双键；
- **手势**：pending 卡右滑通过 / 左滑拒绝，滑程 40% 出底色预览，松手确认；`task.delete` 与 `anchor.remove` 类**不可手势**，必须点按钮（按钮内二次确认 dialog，文案含对象名与影响）。

### 4.3 diff 区按工具类型渲染（替代现状「payload 前 4 个键」裸显示）

| 工具 | diff 内容 |
|---|---|
| task.create | 标题 / 时间（可读格式「明天 18:00」）/ 优先级 / 父任务 |
| task.update | 逐字段「旧值 → 新值」（旧值灰删除线），最多 4 行，超出「等 N 项」 |
| task.delete | 标题 + 「删除后进入撤销队列」提示，警示色标题 |
| note.create | 标题 + 正文首 2 行预览 |
| note.append | 目标章节名 + 追加内容首 2 行 |
| anchor.create | 对象摘要（消息标题/章节名/文件名）→ 任务标题，链环图标 |
| anchor.remove | 同上 + 移除语义 |
| message.set_priority | 消息摘要 → 优先级（色点） |
| inbox.triage | 范围摘要（「48 条消息 → 12 条提案」） |

旧值来源：提案 `payload.base`（CRDT 裁决管线提供）；无 base 的创建类不显示旧值列。

### 4.4 冲突裁决呈现（对接 crdt.md §3.2）

- rebase 生效：applied 态 + 下方一行角注「审批期间目标有变化，已基于最新状态生效」；
- superseded：状态标「已被覆盖」，diff 区显示「你的当前值 vs 提案值」对比，按钮 = [重新生成提案]（以当前状态为 base 重新落一条 pending）；
- failed：状态标「失败」+ 原因一行 + [重试]。

### 4.5 待确认区（approvals_page）

- 定位降为「跨对话总账」：分组（按对话 batch）、工具类型筛选 chip、组全选、底部批量条——现状全部保留；
- 底部批量条改规格：`[通过所选(n) filled] [拒绝所选 outlined]`，n 用等宽数字 + AnimatedSwitcher 位次滚动；
- 历史区新增 superseded 分组显示；applied 撤销入口保留；
- 与对话内提案卡共用 §4.2 组件（full 密度），审批动作走同一 `ProposalExecutor`，两处状态实时同步（列表页返回对话页 `_reload` 已有，增补流监听：审批后 op 事件 → 对话页在途订阅刷新）。

## 5. 模型选择器与配置向导（model_picker）

### 5.1 选择器结构

```
AppBar「模型」（选择模式时标题「本对话模型」）
├─ LinkModel 卡（置顶）：状态点 + 设备名 + 在线时模型清单
│   （离线：灰态 +「如何连接」引导链接）
├─ 「默认模型」分区头：当前默认值，点击更改（影响新对话）
├─ 远程端点列表：
│   行 = 状态点 + 名称 + 模型名 + [vision 徽章] + 延迟（ms）
│   选择模式：点击即选并返回；管理模式：点击编辑
└─ FAB/底钮 [+ 添加端点] → 配置向导（§5.2）
```

- 状态点 = 最近一次连通性测试结果（进入页面时对可见端点自动各测一次，结果行内展示，不再只靠 SnackBar 一闪而过）；
- 选择模式下，当前生效项右侧显示 ✓，顶部另有「跟随默认」项（清除每对话覆盖）；
- 删除端点：左滑 → 确认 dialog（列出绑定它的对话数，删除后这些对话回退默认模型）。

### 5.2 配置向导（三步，全屏 push + Stepper）

1. **选模板**：供应商卡片网格（OpenAI / DeepSeek / 通义 / 智谱 / Moonshot / 自定义），卡片 = logo 字母块 + 名称；选中预填 baseUrl + 候选模型名；
2. **填密钥 + 测连接**：apiKey 输入（明文/密文切换眼睛钮）→ [测试连接]：调 `GET <baseUrl>/models`，成功显示「连接成功 · 123ms · 发现 N 个模型」并把模型名变成**下拉选择**；失败分类提示（无法连接 / 401 密钥无效 / 404 路径有误，附排查建议一行）；
3. **能力与保存**：vision 开关（按模型名启发式预勾）+ 备注名（缺省 = 供应商名）+ [保存并测试对话]（可选：发一条 ping，端到端验证后 toast「一切就绪」）。

任一步可返回上一步；只有测试连接通过才放行「下一步」（自定义模板允许跳过但标黄「未验证」）。

### 5.3 诊断共享

端点最近一次失败原因持久化（`AiEndpoint` 加 `lastError`/`lastLatencyMs` 字段，存 SharedPreferences JSON、无 DB 迁移）：选择器行、对话页错误横幅、配置向导显示同一份；对话页回合错误时横幅文案可直接引用（「该端点上次测试：401 密钥无效」）。

## 7. 边界态与异常清单

| # | 场景 | 规格行为 |
|---|---|---|
| 1 | 回合进行中离开对话页 | 回合服务自持（现状）；列表页呼吸点；回来重新订阅（现状保留） |

| 9 | LinkModel 掉线中途 | 回合错误横幅 + 诊断（「连接中断，上次测试正常」）；不重试已产生的提案落库 |
