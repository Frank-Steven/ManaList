# 助理体验重设计（Assistant v4）：交互 · 外观 · 配置

> 状态：v1.1（2026-11-08）
> 定位：助理域交互、外观、配置体验的整体重设计，细化并取代 `ui-structure.md` §6.3 与 `design-v3.md` §5.1/§5.5 中的对应 UI 约定。机制底座（原子工具、全量审批、执行链路）不变，仍见 `assistant.md`；并发语义见 `docs/crdt.md`。
> v1.1：逐组件/逐状态的落地规格（尺寸、色彩、动效、手势、边界态、文件级改动清单）见配套详细设计 `docs/assistant-v4-ui.md`。
> 参考基线：ChatGPT、Claude、Cursor、Perplexity、Gemini 等成熟 Agent 产品的已验证模式——只采纳在「手机小屏 + 全量人工审批」约束下成立的部分，不照搬桌面形态。

---

## 1. 从成熟 Agent 借鉴什么（以及不借鉴什么）

| 成熟模式（出处） | 采纳方式 |
|---|---|
| 流式输出 + 随时停止（全员） | 已有；补强：停止后保留已生成正文与已落提案，可「接着写」续跑 |
| 工具调用折叠卡（Claude / Cursor） | 已有工具卡；升级为统一的「步骤时间线」样式（§3.2） |
| 对话内直接审批变更（Cursor accept/reject） | **核心借鉴**：提案卡片在对话流内直接「通过 / 拒绝」，不必跳待确认区（§4.1） |
| 编辑用户消息并分叉重跑（ChatGPT / Claude） | 已有重试/编辑/撤回；补「分支」语义提示（§3.4） |
| 空对话的开场建议（Perplexity / Gemini） | 新增：按库/任务真实数据生成的情境化建议 chips（§3.3） |
| 斜杠命令 / 快捷指令（Cursor / Claude Code） | 轻量采纳：输入框 `/` 唤起固定指令集（§3.3），不做自定义命令编辑器 |
| 模型能力标签与每对话切换（全员） | 升级模型选择器：能力徽章、连通性状态、每对话覆盖与全局默认分离（§5） |
| 上下文用量可见（Claude / Cursor） | 新增：附件 token 预算条（§3.5） |
| 对话搜索 / 置顶 / 自动命名（ChatGPT） | 对话列表补齐三项（§2.1） |
| **不借鉴** | 桌面双栏 artifacts/canvas、多 Agent 编排视图、自定义 GPT 商店、语音模式——超出首版范围与手机形态 |

## 2. 助理 Tab 结构

```
AppBar「助理」  actions: [待确认区(角标) | 搜索]
对话列表（可搜索/置顶） + FAB 新对话
└─ 对话页（push，全屏对话流 + 底部输入区）
   ├─ 顶栏：对话标题（点击改名/模型切换/菜单）
   ├─ 对话流：消息 + 工具步骤卡 + 内联提案卡
   └─ 输入区：附件条 / 输入框（/ 指令）/ 发送·停止键
```

### 2.1 对话列表

- **自动命名**：首回合完成后由模型生成一句标题（本地规则截断兜底），替换「首条消息截断」；长按可改名（保留）。
- **置顶与搜索**：左滑置顶；AppBar 搜索按标题 + 正文全文过滤。
- **在途状态**：保留呼吸圆点 + 阶段标签（`turnsVersion`），新增「有待审批提案」角标（该对话 pending 数），让「哪个对话在等我做决定」在列表层可见。
- **模型标识**：每条对话副标题显示当前模型名缩写，一眼识别「这条对话用的是哪个脑」。

### 2.2 对话页顶栏

- 标题行：对话名（默认两行截断省略）；副标题行：当前模型 + LinkModel/远程通道状态点（绿=在线、灰=远程、红=不可用）。
- 点击模型名唤模型选择器（选择模式），比进菜单少一跳；**有在途回合时先弹后果说明 sheet**（当前回合用旧模型跑完、切换自下一回合生效、非 vision 模型不附图片、预算条重算），细则见 `assistant-v4-ui.md` §3.2。
- 溢出菜单：改名、导出对话（markdown）、清空上下文重开（保留提案）、删除。

## 3. 对话页交互

### 3.1 消息呈现

- **助理消息全宽时间线**（Claude/ChatGPT 式），弃用气泡：长 markdown 正文用满屏宽，阅读效率高于 82% 宽气泡。用户消息保留右对齐实心 pill（短文本，视觉上是「我说的话」）。时间戳收敛到长按详情，不常驻（现状气泡角时间戳移除，降噪）。
- 流式：呼吸圆点光标内联末尾（已有）；**平滑追加**——新 token 成段淡入而非逐字硬跳。
- 回合错误横幅保留 errorContainer 样式，附「重试」行内按钮。

### 3.2 工具步骤时间线

工具调用与只读查询统一渲染为**步骤卡**（左对齐、细竖线串联，类 Claude 工具展示）：

- 折叠态：一行 = 图标 + 中文动作名 + 状态（转圈/绿勾/红叉）+ 一句话摘要（「查询了 12 条待办」）；
- 展开态：参数摘要 + 结果摘要（只读工具）或跳转提案卡（写工具）；
- 默认折叠、回合结束后整组可收成一条「共 N 步」；不再裸露 JSON（沿用 v3.7 定稿）。

### 3.3 输入区

- 圆角胶囊容器（已有）；`/` 唤起**指令面板**（固定集：`/整理收件箱`、`/总结`、`/建任务`、`/翻译`，即高频意图的提示词模板，插入输入框可再编辑）；
- 空对话显示**情境化建议** chips（最多 3 条，按真实数据生成：收件箱 pending>0 →「帮我整理收件箱」；今天有任务 →「排一下今天的时间」；无数据 →「记一篇笔记」），点击即发送；
- 附件条：chip 横滑（已有），新增附件总预算提示（§3.5）；长按 chip 预览对象详情；
- 发送键回合中变停止键（已有）；停止后输入框自动填「继续」快捷按钮，续跑不丢上下文。

### 3.4 消息操作

长按消息 → 操作菜单（复制 / 重试 / 编辑 / 撤回，沿用 v10 截断语义）；编辑后从该点重跑，界面在分叉处显示细分隔线「已从这里重新生成」——借鉴 ChatGPT 的分叉提示但不做多分支树（手机屏不承载树形导航）。

### 3.5 上下文预算可见

附件条右端显示预算条（已附正文估算 token / 该模型上下文上限），超 80% 变黄、超限变红并阻止发送（提示移除附件）。借鉴 Claude/Cursor 的上下文指示，防「附件挂太多模型瞎答」。

## 4. 审批体验（重设计重点）

### 4.1 对话内内联审批（Cursor 模式）

提案卡片从「摘要 + 前往待确认区」升级为**可直接裁决**：

- 卡片 = 工具图标 + 动作摘要 + 关键 diff（任务：标题/时间/优先级前后值；锚点：对象 → 任务；消息标记：消息摘要 → 优先级）+ 底部「通过 ✓ / 拒绝 ✕」双键；
- 通过后原位变为「已生效」态（绿边、可撤销 10s）；拒绝变灰沉底；
- 冲突裁决（`crdt.md` §3.2）在卡片上直接呈现：rebase 生效显示「已基于最新状态生效」；superseded 显示「已被你的修改覆盖：旧值 → 新值」+「重新生成」按钮；
- 同批次多条提案时，组尾出现「全部通过（n）」条——批量入口就在对话里，待确认区退居二线。

### 4.2 待确认区：从主入口降为总账

- 保留为**跨对话总账**：全部 pending 按对话分组，筛选（工具类型 chip）、批量通过/拒绝不变；
- 入口角标保留；卡片组件与对话内提案卡**同一组件**（已是 §7 定稿，本次仅补双键密度）；
- 「历史」折叠区补充 superseded 状态与撤销入口。

### 4.3 审批手势与反馈

- 提案卡支持右滑通过 / 左滑拒绝（与消息列表手势语言一致），破坏性例外：`task.delete` 类提案必须点开确认（§4.1 卡片内二次确认），不可手势秒批；
- 触觉反馈分级：通过 = 轻振，批量通过 = 中振，拒绝 = 无振（消极动作不打断）；
- 默认勾选策略不变（仅 junk 标记默认勾选，`design-v3-details.md` §3.3）。

## 5. 配置体验（模型与端点）

现状问题：远程端点是「一张裸表单」（baseUrl/apiKey/model 手填），无校验无引导，配错只能等对话失败。

### 5.1 配置向导（三步）

1. **选模板**：预设供应商卡片（OpenAI / DeepSeek / 通义 / 智谱 / Moonshot / 自定义 OpenAI 兼容），模板预填 baseUrl 与推荐模型名，用户只填 API Key；
2. **测连接**：「测试连接」按钮 → 拉 `GET <baseUrl>/models`（OpenAI 兼容通约），成功则**模型名下拉可选**（不再手拼模型字符串），失败给具体原因（网络/401/404 路径错），附延迟毫秒数；
3. **能力开关**：vision 开关按模型名启发式预勾（gpt-4o/qwen-vl 等），可手改；保存前可发一条「ping」测试消息验证端到端。

### 5.2 模型选择器重构

- 分两组：**LinkModel（电脑端）**置顶卡片——在线状态、本地模型列表、连通性探测结果实时显示；**远程端点**列表——每项显示状态点（上次测试：✓ + 延迟 / ✗ + 原因）、模型名、vision 徽章；
- **全局默认与每对话覆盖分离**：选择器顶行设「默认模型」（新对话用），对话内进入则为「本对话模型」覆盖，卡片标注「覆盖默认」；
- 编辑/删除入口收敛到长按或右滑，列表主职责是「选」。

### 5.3 诊断与留痕

- 每次端点调用失败记录最近一条原因（HTTP 码/超时/解析失败），在选择器条目与对话错误横幅间共享同一份诊断；
- LinkModel 通道状态（adb 在线与否）在选择器与对话页顶栏状态点一致显示，消除「为什么走了远程还这么慢」的困惑。

## 6. 外观规范（助理域视觉语言）

| 元素 | 规范 |
|---|---|
| 助理消息 | 全宽、无气泡、markdown 渲染；代码块等宽字体 + 复制按钮；引用块左侧竖条；表格横向滑动 |
| 用户消息 | 右对齐 primary 实心 pill，最大宽 82%，纯文本 |
| 步骤卡 | surfaceContainerLow 底、无描边、细竖线串联；状态图标 16px |
| 提案卡 | surfaceContainerHigh + 状态色左边条（pending 黄/applied 绿/rejected 灰/failed 红/superseded 蓝灰）；双键主从分明（通过=实心、拒绝=描边） |
| 建议 chips | 输入区上方横滑，secondaryContainer 底 |
| 状态点 | 通道/模型在线状态统一 8px 圆点（绿/灰/红），全助理域同一语义 |
| 动效 | 流式淡入 ≤150ms；卡片展开收起 200ms；回合开始/结束的状态切换走 AnimatedSwitcher（对齐全 App 300ms 内分档规范，见 `ux-fixes-2026-11.md` §3） |
| 字号 | 助理正文 16sp（对话正文比列表密度优先），代码 13sp，步骤卡摘要 13sp |
